## 二、运行环境要求

### 2.1 解释器

- **Python 3.10 及以上、64 位**（本项目实际使用 3.12.3）。
- 依赖必须装在**你实际运行脚本的那个解释器**里 —— 不同解释器之间装的包不互通，
  「明明装了却提示缺依赖」基本都是这个原因。
- 脚本启动时会先检查依赖：缺了会直接打印**当前解释器路径**和**一行可复制的 pip 安装命令**，照着执行即可。

> 脚本里已经屏蔽，避免输出被警告刷屏。

### 2.3 pip 源与 TLS 假故障

现象：用 PowerShell 的 `Invoke-WebRequest` 测 pypi 镜像会报「基础连接已经关闭」，
但用 Python 的 `urllib` 访问同一地址是 200 —— 这通常只是 PowerShell 的 TLS 栈问题，
**不是网络真的不通**。pip 走的是 Python 自己的 SSL，正常可用。

**建议**：统一用 `python -m pip`（不要用 `pip.exe` 直连），并显式指定 HTTPS 镜像：

```powershell
python -m pip install -i https://mirrors.aliyun.com/pypi/simple --trusted-host mirrors.aliyun.com 包名
```

### 3.2 模型名与服务端要配套

| 服务端 | 地址 | 可用的模型名 |
|--------|------|--------------|
| 聚合网关 | `https://tokenrhythm.studio/v1` | `deepseek-v4.1-flash-1017`（**本章默认**） |

同一个模型在两处叫法不同：把 `deepseek-v4.1-flash-1017`（带点）发给方舟会 404，
把 `deepseek-v4-1-flash-261017`（短横线）发给网关也不行。所以 `RAG.py` 把
`LLM_BASE_URL` / `LLM_MODEL` 拆成两个独立配置项，换服务只改 `.env`，不用动代码。

### 3.3 豆包向量模型：首选不可用时的自动回退

首选向量模型 = `doubao-embedding-text-240715`（方舟文本向量接口 `POST /embeddings`）。
但用当前账号实测：

```text
POST /api/v3/embeddings  {"model":"doubao-embedding-text-240715", ...}
-> 404 InvalidEndpointOrModel.NotFound（该模型未开通 / 无访问权限）
```

（`GET /api/v3/models` 能看到这个模型 ID，但当前 Key 没有调用权限。）

**处理**：`ArkEmbeddings` 会按 `EMBEDDING_MODEL` → `EMBEDDING_FALLBACKS` 顺序自动探测，
第一个能用的就固定下来，并在日志里明确打印「已自动回退」。目前生效的是：

```text
doubao-embedding-vision-251215  走 POST /api/v3/embeddings/multimodal  维度 2048
```

**想让首选模型真正生效**：去火山方舟控制台 →「开通管理」开通 `doubao-embedding-text-240715`
（或换一个已开通该模型、或企业版账号的 Key），然后 `.env` 保持 `EMBEDDING_MODEL` 不变即可，
第一次探测就会走文本向量接口 `/embeddings`，无需改代码。

## 四、PDF 与索引

### 4.1 PDF 放哪里

**固定放在 `RAG.py` 同级目录**：`03RAG检索/test.pdf`。换成自己的文档时，用同名文件覆盖后加 `--rebuild` 运行。

### 4.2 索引缓存

`meta.json` 记录 PDF（文件名 / 大小 / 修改时间）、向量模型、切分参数。三者都没变就直接复用本地索引，
不再重新向量化；换 PDF、换向量模型、改 `CHUNK_SIZE` 会自动重建。手动重建：

```powershell
python RAG.py --rebuild
```

真实模式和模拟模式使用**两套独立的索引目录**（`faiss_rag_index` / `faiss_rag_index_mock`），
因为两者向量维度不同（2048 vs 256），不能混用；`--rebuild` 只会重建当前模式对应的那份索引。

### 4.3 faiss 写中文路径失败

```text
RuntimeError: ... FileIOWriter ... could not open ...\03RAG检索\faiss_rag_index\index.faiss for writing
```

原因是 faiss 在 Windows 上用 C 的 `fopen`，路径编码按 ANSI 走，带中文（「03RAG检索」）就打不开。
**解决**：不调 `save_local`，改用 `serialize_to_bytes()` 把整个向量库 pickle 成 bytes，
再用 Python 的 `open` 写文件（Python 处理 Unicode 路径没问题）；读取时用 `deserialize_from_bytes()`。
索引文件：`faiss_rag_index/index.pickle` + `meta.json`。

## 五、怎么运行

> 在 `03RAG检索` 目录下执行；`python` 指已装好依赖的解释器。
> 脚本结构、每个函数为什么这么写，见另一份文档：[RAG.py代码详解.md](RAG.py代码详解.md)。

```powershell
# 1) 环境自检（解释器 / 依赖 / Key / 大模型 / 向量模型 / PDF / 索引）
python RAG.py --doctor

# 2) 首次运行：构建向量库 + 跑内置 4 个测试案例
python RAG.py

# 3) 直接提问（可传多个问题）
python RAG.py "大会在什么时间、什么地点举办？"

# 4) 强制重建向量库（换了 PDF / 向量模型时）
python RAG.py --rebuild

# 5) 调整检索条数
python RAG.py --top-k 5 "这份文档主要讲了什么？"

# 6) 离线模拟模式：不调用任何 API，用假模型 + 假向量演示整条 RAG 流程
python RAG.py --mock
```

## 七、常见问题

**Q：报 `❌ 缺少依赖：faiss-cpu`？**
按提示把那行 pip 命令复制执行（装到你正在用的解释器里），或者换成已装齐依赖的解释器。

**Q：报 `❌ 没有可用的豆包向量模型`？**
检查 `.env` 的 `ARK_API_KEY` 是否有效，以及方舟控制台是否开通了向量模型；报错信息里会逐条列出每个候选模型的失败原因。

**Q：报 `大模型调用失败：...401` / `403`？**
`LLM_BASE_URL` 和 Key 必须配套：网关 Key 不能发给方舟，方舟 Key 也不能发给网关。

**Q：回答里模型「思考」很久 / 判断节点总是 False？**
`deepseek-v4.1-flash-1017` 会先消耗 token 做推理。脚本里的「是否需要检索」判断**故意不限制 `max_tokens`**，
因为实测限制太小（如 8 / 32 / 64）会返回空字符串，导致判断失真；模型返回空时脚本会用关键词兜底。

**Q：想换成 Chroma / 别的 PDF？**
把 `build_or_load_index()` 里的 `FAISS` 换成 `langchain_community.vectorstores.Chroma` 即可，
PDF 直接覆盖 `test.pdf` 后加 `--rebuild` 运行。

**Q：想不联网先看看流程？**
加 `--mock`：用假模型 + 假向量，不调用任何 API（没有 Key 时也会自动降级到该模式）。
